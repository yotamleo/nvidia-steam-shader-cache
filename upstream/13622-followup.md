Follow-up with two more results from the same machine:

1. **An isolated driver cache stays warm.** With `__GL_SHADER_DISK_CACHE_PATH`/`_APP_NAME` pointing at a private dir (so the merger never touches it), the first launch wrote 2.46 GB of new cache. The relaunch wrote 0 bytes in its first 3 minutes and 65 MB over a whole match. The driver's own cache handles size by itself (it rolls `overwatch1.bin` etc.); the wraparound only happens in Steam's merged file.

2. **Part of Steam's precompiled NVIDIA cache doesn't match what the game needs.** I recovered all 262,547 entries of the merged file (including the 50,673 wrapped ones) into shards under 2 GiB and gave them to the game read-only. The driver opened them, but the game still recompiled 50,164 keys from the first shard. For those keys, the record the game wrote has the same 16-byte TOC key but different header bytes 20..28, a different size and a different payload (2,000 of 2,000 sampled pairs). So beyond the offset overflow, some precompiled entries are compiled differently from what `Overwatch.exe` produces, perhaps because `fossilize_replay` doesn't get the game's driver application profile. That would explain recompiles even below 4 GiB.
